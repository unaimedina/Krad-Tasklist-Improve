## Key design decisions (for reviewers)

- **No agent API in the extension SDK.** Tasks run by opening a terminal (`terminals` permission) with the
  agent's CLI and a one-line prompt that points at the plan file; Krad shows it as an agent session.
- **State comes from the Krad agents bus** via `krad agents watch --json` (an extension is a bus "Client":
  list/watch only — it cannot `spawn`, which is lead-only).
- **The outcome comes from the plan status**, not the agent state: the executor sets its row to DONE or
  BLOCKED; an agent that stops without doing so becomes "needs review".
- **Parallel = git worktrees** named like Krad's own (`<repo>.worktrees/<id>-<slug>`, branch
  `tasklist/<id>-<slug>`); merging stays with the user.
- **Variants**: a task can be handed to 2–4 agents with `krad variants run`, compared in Krad's Variants view.

## Findings considered and rejected

- Spawning Workers through `krad spawn` from the extension: refused by the bus for non-lead callers.
- Using app events (`events/subscribe`): only in the unreleased SDK (api 1.2); `@krad-ade/extension@0.4.0`
  lacks it. Revisit later (noted in plans 004 and 005).
- A webview / rich-text Markdown editor: Krad views cannot run code; editing uses Krad's editor or a
  multiline form field.
